# 🪶 小羽毛 AI 新闻早报

> 每天清晨，中文世界的 AI 新闻第一杯咖啡。

**架构**：双层流水线——脚本层做确定性工作，Agent 做创造性策展。

```
cron 触发 (每日 07:00)
  ┌──────────────────────────────────────────┐
  │  脚本层 — 确定性工作（3 步，~60s）        │
  │                                          │
  │  ① python3 fetch_ai_news.py               │
  │     → candidates.json (原始候选池)         │
  │  ② python3 build_daily_data.py             │
  │     → daily_data.json (去重+结构化草稿)    │
  └────────────────┬─────────────────────────┘
                   ↓ daily_data.json (raw draft)
  ┌──────────────────────────────────────────┐
  │  Agent 层 — 创造性策展（核心升级点）       │
  │                                          │
  │  ③ 选文 × 值判断（不是权重排序）           │
  │  ④ 标题重写（像编辑那样写）                 │
  │  ⑤ 摘要润色（补充标题外的新信息）           │
  │  ⑥ 标签分配（12 分类，精准匹配）           │
  │  ⑦ 产品雷达甄别（具体工具，不是集合页）     │
  │  ⑧ 今日寄语（基于当日最强信号的编辑手记）   │
  └────────────────┬─────────────────────────┘
                   ↓ daily_data.json (curated)
  ┌──────────────────────────────────────────┐
  │  发布层 — 格式化 + 部署 + 推送             │
  │                                          │
  │  ⑨ python3 format_feishu.py               │
  │  ⑩ update_news_ts.py && npm build/deploy  │
  │  ⑪ 飞书推送（message tool）                │
  └──────────────────────────────────────────┘
```

## ⚙️ 脚本层（确定性工作）

### ① fetch_ai_news.py
- 16 个 RSS 源（15 国际 AI + 1 三花AI中文精选）
- 5 个产品平台（Product Hunt / GitHub / Toolify / HN / Trustmrr）
- Google Translate 自动翻译（默认开启）
- 输出：`candidates.json`

### ② build_daily_data.py
- 结构化补全 + 三重去重（URL 精确 + Jaccard 相似度 + 48h 历史交叉）
- 标题修剪 + 摘要截断 + 实体识别
- 产品平台污染检测 + 兜底
- **不生成金句，不分配标签，不做质量门禁** — 全部留给 Agent
- 输出：`daily_data.json`

## 🧑‍🎨 Agent 层（核心策展）

这是每日早报的品质来源。**脚本只能产出草稿，你要把它变成一份值得早上打开的内容。** 以下每一步都是你的职责。

### ③ 选文（从候选人中挑选 18 条）

**原则**：不是脚本的权重排序取前 18，而是你阅读所有候选后做的价值判断。

| 该做的 | 不该做的 |
|--------|---------|
| 覆盖多源（避免同一源包场） | 机械取权重最高 |
| 判断每条新闻的独特价值 | 全盘接受脚本排序 |
| 保持多样性（模型/产品/行业/资本/研究） | 偏向某一主题 |
| 候选不足 18 条时如实说明 | 用低质量候补充数 |

> 🔴 **硬性要求**：如果某条新闻的主题聚类对方框内的条目有"历史重复"嫌疑（完全相同的主题/事件已在前几天出现过），可以降级或移除。

### ④ 标题重写（每条 ≤20 字中文）

**目标**：让读者一眼看清"这是谁的什么事"。

| ❌ 脚本水平的标题 | ✅ 编辑级别的标题 |
|------------------|------------------|
| Mesh LLM | Mesh LLM：把你的多台设备池化为一个 GPU 集群 |
| 我间谍 | 我间谍——好莱坞的智能眼镜早就来了 |
| OpenAI bets on families | OpenAI 招产品经理做家庭体验，AI 从开发走向日常 |
| 视频2PPT | video2PPT：用 AI 把视频自动转成 PPT |

**规则**：
- 必须包含公司/产品英文名（保留原文）
- 说清具体事件，不要抽象概括
- 如果原标题是中文翻译残缺（如 "我间谍"），完全重写
- 绝对禁止：`新动态` `新能力` `今日观察` `值得关注`
- 已存在的 map：`'聊天GPT工作' → 'ChatGPT Work'`, `'第二条军规' → 'Second Rule'`

### ⑤ 摘要润色（每条 ≤120 字中文）

**原则**：补充标题之外的新信息。

- ✅ "Mesh LLM 是一个开源项目，能将用户多台机器上的 GPU 和内存池化，对外暴露兼容 OpenAI 的 API。通过 ZeroMQ 和 gRPC 实现设备间通信。"
- ❌ "值得关注其影响"（空话）
- ❌ 只是重复标题

### ⑥ 标签分配（每条 ≤3 个）

从以下 12 个分类中选择最匹配的：

`资本` `模型` `Agent` `基础设施` `开源` `产品` `研究` `政策` `应用` `硬件` `行业` `全球`

> 注意：脚本可能给每条新闻赋了 `capability_tags`（泛指标签如 "AI Coding Agent"），你需要替换为以上 12 类精确标签。

### ⑦ 产品雷达甄别（5 个具体产品）

**产品门禁**：
- 必须是**具体产品/工具/项目**，不是平台集合页
- `Toolify｜Toolify` → ❌ 判定为退化，抓具体条目
- 产品名（title）为空 → ❌ 退化
- 平台出现 RSS 新闻源名（TheVerge/TechCrunch/等） → ❌ 退化
- 摘要必须提炼"解决什么问题 + 面向什么场景"

如果某平台当天没抓到具体产品，**宁可不输出**也不放集合页充数。

### ⑧ 今日寄语（≤90 字 — 编辑手记）

> **这是整个早报的灵魂所在。脚本不会帮你写。你的判断决定今天的寄语质量。**

**要求**：
- 必须引用至少 1 条当日具体新闻、公司动态或趋势
- 必须像真实编辑的手记，读完后能说出"哦，原来今天 AI 行业发生了这个"
- 时效性强：今天才成立，明天未必
- 自然的中文表达，不是数据报告的开头

**鉴别标准**：

| ✅ 高质量的 | ❌ 低质量的 |
|------------|------------|
| 引用具体新闻/公司/事件 | 只说"X个方向出现Y条动态" |
| 有编辑态度的判断 | 空泛推进词（"值得关注""值得留意"） |
| 今天独有的观察 | 任何一天都通用的句子 |
| 例如："OpenAI 和 Anthropic 今天同时在'家庭场景'上出手…" | 例如："今日最值得留意的方向是 Agent 工作流——3 条动态中…" |

**金句退化模式**（被质量门禁捕获后须重写，**不得通过**）：
- `方向连续冒头` `信号同时出现` `点状创新进入并行推进`
- `产品化节奏与商业落地` `持续性与外溢影响`
- `最值得留意的方向是` `特别值得一读`
- `放在一起看，这几个动态形成了一个值得追踪的方向`
- **任何"X条动态中..."开头的句式**
- 任何人读完后觉得"这句放昨天或明天也可以"

### 质量自检清单

每次交付前逐项打勾：

- [ ] 选文是否覆盖多源、多维？
- [ ] 每条标题是否说清"谁的什么事"？
- [ ] 每条摘要是否补充了标题之外的信息？
- [ ] 标签是否在 12 分类内且 ≤3 个？
- [ ] 产品雷达是否全是具体产品/工具？
- [ ] 今日寄语是否引用了当日具体新闻？
- [ ] 今日寄语是否读起来不像是昨天的？

2️⃣ 【标签】标题

━━━ 🛍️ 产品雷达 ━━━

  产品名｜平台

**格式规则**：
- 💬 今日洞察：你的编辑手记，不允许模板
- 每条新闻块严格竖排：标题 → 📰 → 📝 → 🔗
- 底部仅显示条数统计
- 如果源覆盖率过低（活跃源 < 12），额外加一句说明

### 失败处理

| 失败场景 | 处理方式 | fallback |
|----------|---------|----------|
| `fetch_ai_news.py` 途中崩溃，`candidates.json` 未生成 | 报告失败来源，尝试用已有的 `daily_data.json` 回退 | 如果完全无数据 → 跳过今日推送 |
| `build_daily_data.py` 失败，`daily_data.json` 未生成 | 报告失败原因，查看 `candidates.json` 是否可用 | 手动跑 `build_daily_data.py` 或跳过今日 |
| 候选不足（< 18 条） | 保留现有候选，**不要用低质量候补充数** | 如实推送少量优质条目，底部说明 |
| 活跃源 < 50%（< 8/16） | 底部标注源覆盖率，但要检查是否有 URL 迁移或 RSS 格式变更 | 查看最近 3 天的 `meta.source_stats` 判断是否为趋势性失效 |
| 某产品平台数据为空（所有产品被过滤） | 静默跳过，不得用集合页充数 | 用 `meta.fallback_products_added` 确认有无兜底 |
| 引语质量门禁后不合格 | **不得通过被门禁的引语**，重新撰写 | 如果当日素材确实无法产出真洞察，可以省略今日寄语 |
| Vercel 部署失败 | 不影响飞书推送，单独重试或报告用户 | `bash scripts/deploy.sh 2>&1` 排查错误 |
| 推送渠道异常 | 消息保存到本地 `output/` 目录 | 手动复制推送 |

### 每日验证节点

交付前检查以下 3 个节点，任一失败则标记今日异常：
1. `daily_data.json` 存在且 `news` 数组非空
2. `quote`（今日寄语）不是任何一条金句退化模式
3. 站点可达：`curl -sI https://xiaoyumao-news-web.vercel.app` 返回 200

## ❌ 反例清单

### 标题反例（绝对不要用）
- `我间谍` — ← 英文 "I Spy" 直译残缺，**必须**完全重写
- `聊天GPT工作` — ← "ChatGPT Work" 的翻译残留
- `第二条军规` — ← 不明所以的翻译
- `视频2PPT` — ← 保留英文缩写但说明做什么
- `[Source] 今天最火的 N 篇 AI 文章` — ← 不是新闻标题

### 标签反例
- 给「OpenAI 家庭产品经理」打 `硬件` ❌ → 应该 `产品`
- 给「Meta 放弃 Muse」打 `全球` ❌ → 应该 `产品` `应用`
- 给「NVIDIA 显卡编程教程」打 `产品` ❌ → 应该 `硬件` `Agent`
- `capability_tags`（如 "AI Coding Agent"）不是 12 分类标签，**Agent 必须替换**

### 引语反例（退化模式）
- `今日最值得留意的方向是 X——Y 条动态中...`
- `今日「X」方向出现 Y 条动态`
- `X 方向多个信号同时出现`
- `放在一起看，这几个动态形成了一个值得追踪的方向`
- `产品化节奏与商业落地正在同步推进`
- 任何可在任意日期重用的句式

### 产品雷达反例
- `Toolify｜Toolify` — ← 平台名占位，不是具体产品
- `Product Hunt｜Product Hunt` — ← 同上
- 标题为空的产品条目 — ← 平台抓取退化，不输出
- 归类为 `news-site` 的条目混入产品
